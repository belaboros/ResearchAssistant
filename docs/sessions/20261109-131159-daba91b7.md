**Why the root fits this project:**
- **The specs drive the work.** Here they come before any code, so it makes sense for them to sit next to `src/` and `tests/`. Keeping them at the root says they're the source of truth.
- **The paths stay short.** CLAUDE.md, all five skills and the reviewer subagent refer to `ideas/NNNN-*` and `specs/NNNN-*/`. Short paths are easier to `@`-mention and for Claude to find.
- **Other tools do the same.** GitHub's Spec Kit, for example, keeps `specs/` at the repo root.

**When `docs/` would be the better choice:**
- The root fills up once code, config and CI files arrive, and you want everything non-code in one place.

- You'll add more kinds of documents, such as decision records (ADRs), research notes or user guides. Then `docs/ideas/`, `docs/specs/` and `docs/adr/` group neatly.

Moving them later is easy: the paths only appear in CLAUDE.md, the five skills, the reviewer subagent and a few links inside the idea and spec files. One search-and-replace updates them all.

My recommendation: commit short, curated summaries of each session to `docs/sessions/`, not the raw chat transcripts. Keep raw transcripts out of the main branch. I've captured this as [idea 0002](docs/ideas/0002-store-chat-history-in-repo.md) and logged your question and my answer there.

**Why not commit raw transcripts.** Claude Code saves each session as a JSONL file in `~/.claude/projects/<project>/`. Committing those to this repo causes several problems:

- **Secrets and personal data.** A transcript holds every tool result: the full contents of files Claude read, command output, environment details, your email address and local paths. If a token or `.env` value appears once, it stays in git history. The Apache license suggests the repo is or will be public, which makes this the biggest risk.
- **Noise.** Each session is several megabytes of JSON. Diffs can't be reviewed, and the repo keeps growing.
- **Context pollution.** Later sessions would find old transcripts when they search the repo. Claude would then read past chat, including abandoned ideas and earlier mistakes, instead of the specs and ADRs that are the source of truth.
- **Duplication.** What's worth keeping long-term is already captured: original ideas and every question and answer in `docs/ideas/`, decisions in ADRs, requirements in specs, and code changes in commits.

**What I'd set up instead:**

1. **Curated summaries (main branch).** At the end of each session, a hook writes `docs/sessions/YYYY-MM-DD-<slug>.md`. It covers what you asked, what was decided, and which files, ideas, ADRs and commits were affected. Each summary is small, reviewable and contains no secrets.
2. **Raw transcripts, only if you need a full audit trail.** They would go to a separate private repo (best), or at least an orphan branch that never merges into `main`. A secret scanner (`gitleaks`) runs before every push. A deny rule in `.claude/settings.json` keeps Claude from reading them back.
